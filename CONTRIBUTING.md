# Contributing

Thanks for your interest in improving exphono!
This guide gets you set up and explains how the project is put together.
If anything here is unclear, opening an issue to ask is welcome.

## Getting set up

You'll need Node.js >= 22.
Then install the dependencies:

```sh
pnpm install
```

Commit the lockfile generated by your package manager (`pnpm`).

## Scripts

| Command | What it does |
| --- | --- |
| `pnpm run build` | Bundle ESM/CJS + type declarations with tsdown |
| `pnpm run test` | Run the tests once with vitest (`pnpm run test:watch` to keep them running) |
| `pnpm run test:coverage` | Run the tests with a coverage report |
| `pnpm run typecheck` | Type-check with `tsc --noEmit` |
| `pnpm run format` | Format the code, writing the fixes (Biome) |
| `pnpm run format:check` | Check formatting without writing (Biome) |
| `pnpm run lint` | Lint the code without writing fixes (Biome) |
| `pnpm run lint:fix` | Lint the code, writing the fixes (Biome) |
| `pnpm run check` | Lint, format and organize imports, writing the fixes (Biome) |
| `pnpm run ci` | The same checks without writing — what CI runs |

Before opening a pull request, make sure the full set passes:

```sh
pnpm run ci && pnpm run typecheck && pnpm run test && pnpm run build
```

## Conventions

- **Formatting and linting is Biome** (`biome.json`) — single quotes, no semicolons, trailing commas, 100-column width.
  Running `pnpm run check` before you commit handles all of it.
- **Tests live next to the code** as `*.test.ts` and run with vitest.
- **Comments and docs are in English** and kept brief.
- **Type-only imports use `import type`** (`verbatimModuleSyntax` is on).

## Pull requests

Keep each change focused and add tests for any new behaviour.

## Releasing (maintainers)

Releasing is one manual step.
From the Actions tab, run the `release` workflow (`workflow_dispatch`) and give it a `version` input — either a bump keyword (`patch` / `minor` / `major` / `prerelease`) or an explicit version like `0.1.0`.
The workflow runs the checks and build, bumps `package.json`, publishes to npm with provenance via **trusted publishing** (OIDC — no `NPM_TOKEN` needed), pushes the version commit and tag, and creates a GitHub Release with generated notes.

Trusted publishing must be configured once on npmjs.com:
package **Settings → Publishing access → Trusted publishers → GitHub**, pointing at this repository's `release.yml` workflow.
